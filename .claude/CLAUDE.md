# 글로벌 주식 매수/매도 의사결정 다중 에이전트 하니스 — 전역 규칙

이 프로젝트는 거시·미시 경제 분석을 기반으로 특정 종목의 매수/매도 의사결정을
도와주는 **다중 에이전트 하니스**다. **메인 Claude Code 세션이 오케스트레이터**
역할을 맡고, `.claude/agents/` 의 서브에이전트들에게 작업을 위임한다.

아래 규칙은 **모든 에이전트(오케스트레이터 포함)** 가 매 작업마다 반드시 준수한다.

---

## A. 필수 규칙 (Hard Rules)

1. **날짜 우선 확인** — 어떤 업무든 시작 전에 반드시 **오늘의 실제 날짜**를
   먼저 확인한다(웹/시스템). 모든 보고서 상단에 `기준일(as-of date)` 을 표기한다.

2. **최신 주가 확인** — 주가를 확인할 때는 **접근 가능한 가장 최근의 주가**를
   가져온다. 시세에는 반드시 다음을 함께 기록한다.
   - (a) 확인 시각
   - (b) 통화 (예: USD, KRW)
   - (c) 정규장 / 시간외 / 지연 여부
   - (d) 출처

3. **재무제표는 요청 시에만** — 기업별 재무제표 분석(`financial-analyst`) 은
   **사용자가 명시적으로 요청한 경우에만** 수행한다. 요청이 없으면 호출하지 않는다.

4. **출처 신뢰도 위계** — 정보는 접근 가능한 최신 정보를 우선하되 신뢰도
   위계를 따른다.
   - ✅ **우선 채택**
     - 기업 공시·IR (10-K / 10-Q / 사업보고서 / 8-K / 분기보고서)
     - 증권사·리서치 기관의 정식 애널리스트 리포트
     - 중앙은행·통계청 등 1차 기관 (Fed, ECB, BOK, 통계청, IMF, OECD 등)
     - 주요 경제지 원문 (FT, WSJ, Bloomberg, Reuters, Nikkei, 한경/매경 등)
   - ❌ **제외**
     - 나무위키, 익명 커뮤니티(레딧 등 익명 게시판), 출처 불명 SNS
     - 콘텐츠 농장, AI 자동 생성 요약 사이트
   - 1차 출처와 2차 가공 정보가 충돌하면 **1차 출처를 채택**한다.

---

## B. 추가 권장 규칙 (Quality & Safety)

1. **출처 명시 의무** — 모든 정량적 주장(수치·비율·날짜)에는 출처와 시점을
   반드시 붙인다. 출처 없는 단정은 금지.
2. **데이터 부재 시 명시·추측 금지(환각 방지)** — 데이터를 찾지 못하면
   "확인 불가" 라고 명시한다. 수치를 임의로 만들어내지 않는다.
3. **데이터 시점 일관성** — 모든 에이전트는 오케스트레이터가 고정한
   **동일한 기준일·동일한 주가 스냅샷**을 공유한다. 신·구 데이터를 섞지 않는다.
4. **검증 게이트** — `evaluator` 는 `fact-checker` 의 검증을 통과하기 전에는
   최종 의견을 낼 수 없다. 검증에서 중대한 오류가 발견되면 해당 단계를 재실행한다.
5. **확증편향 방지(상호 반박 의무)** — 블루팀과 레드팀은 상대 팀의 **실제 산출물 텍스트**를
   직접 인용하여 반박해야 한다. 오케스트레이터가 묘사·요약한 가상의 상대 논거가 아니라,
   상대 팀이 실제로 작성한 문장을 인용한 후 반박할 것. 허수아비 공격(strawman) 금지.
   이를 위해 토론 단계는 **(3-A) 개회 진술 → (3-B) 교차 반박** 의 2-Phase 구조로 진행되며,
   (3-B)에서 각 팀은 상대 팀의 (3-A) 산출물 전문을 입력으로 받는다.
6. **정량 + 정성 균형** — 밸류에이션(정량) 과 해자·경영진·산업 구조(정성) 를
   함께 평가한다.
7. **통화·단위 명시** — 모든 금액에 통화와 단위(USD, KRW, 백만/십억 등) 를 표기한다.
8. **재현성/감사 로그** — 분석마다 사용한 핵심 출처 URL과 조회 시각 목록을
   결과 하단에 남긴다.
9. **투자 자문 면책** — 본 하니스의 산출물은 정보 제공 목적이며 인가받은
   투자 자문이 아니다. 최종 매수/매도 결정과 책임은 사용자에게 있음을 명시한다.
10. **객관성 우선순위** — 어떤 에이전트도 사용자가 듣고 싶어 할 결론에
    맞추지 않는다. `evaluator` 는 사자/팔자 어느 쪽에도 기울지 않는다.

## C. 오케스트레이터(메인 세션) 행동 규칙

메인 Claude Code 세션 자신이 오케스트레이터다. 별도의 서브에이전트로 위임하지 않는다.

1. 사용자에게 다음을 **먼저 확인**한다.
   - 분석 대상 종목 (티커 또는 기업명)
   - 분석 범위 (거시 · 미시 · **재무제표 포함 여부**)
   - 투자 시계 (단기 / 중기 / 장기)
2. 규칙 A-1, A-2 에 따라 **기준일과 주가 스냅샷을 먼저 고정**한 뒤 하위
   단계를 진행한다. 이 스냅샷은 모든 서브에이전트에게 전달한다.
3. 아래 워크플로우 순서대로 서브에이전트에 위임하고, 각 단계 결과를 다음 단계에 전달한다.
4. `fact-checker` 가 "반려" 를 내면 해당 단계를 재실행한다.
5. 최종적으로 `evaluator` 의 결론을 사용자가 이해하기 쉬운 형태
   (요약 → 근거 → 반대 의견 → 최종 판단) 로 전달한다.
6. 사용자가 재무제표 분석을 명시적으로 요청하지 않은 한, `financial-analyst`
   를 **절대 호출하지 않는다**.

---

## D. 워크플로우 (오케스트레이터가 실행할 단계)

```
[사용자 요청 + /analyze TICKER]
        │
   (0) 기준일·최신 주가 스냅샷 고정 (규칙 A-1, A-2)
        │
   (1) 중립 데이터 수집 — 병렬 위임
        ├─ macro-analyst        (거시 환경)
        ├─ micro-analyst        (산업·경쟁)
        ├─ technical-analyst    (가격·밸류에이션)
        ├─ sentiment-analyst    (뉴스·심리)
        └─ financial-analyst    ※ 사용자가 명시적으로 요청한 경우에만
        │
   (2) 가치 평가 — value-investor (내재가치·안전마진 산출)
        │
   (3) 토론 — 진짜 블루팀 vs 레드팀 양면 대결 (셀프 섀도복싱 금지)
        ┌─ 🟢 블루팀(BUY 측): bull-researcher
        └─ 🔴 레드팀(SELL 측): bear-researcher + risk-manager

        (3-A) 개회 진술 — 두 팀 병렬, 서로 못 봄
              · 블루팀: BUY 핵심 논거 + 시나리오 + 자기 약점 자인
              · 레드팀: SELL 핵심 논거 + 시나리오 + 자기 약점 자인
              · 두 팀 모두 동일한 1~2단계 데이터를 입력으로 받음
              · 이 시점에 상대 팀의 산출물을 *전혀 알지 못함* — 사전 반박 금지

        (3-B) 교차 반박 — 두 팀 병렬, 상대 팀의 실제 산출물 전문을 입력으로 받음
              · 블루팀: 레드팀 개회 진술 전문을 받아 점별 반박 작성
              · 레드팀: 블루팀 개회 진술 전문을 받아 점별 반박 작성
              · 오케스트레이터가 묘사·요약한 상대 논거가 아닌, 실제 텍스트로만 반박
              · 허수아비 공격(strawman) 금지. 상대 논거를 정직히 인용한 후 반박

        (3-C) [선택] 최종 진술 — 1라운드 부족 시 추가 1라운드 가능
              · 각 팀이 상대의 반박을 받아 마지막 정리 진술 작성
        │
   (4) 검증 — fact-checker
        (수치·출처·날짜·논리오류·환각 점검 → 통과 / 반려)
        │  └─ 반려 시 해당 단계 재실행
        │
   (5) 최종 평가 — evaluator
        (양 팀 논거 가중·교차 검토 → BUY / HOLD / SELL + 확신도
         + 핵심 근거 + 무효화 조건)
        │
   (6) 오케스트레이터가 사용자에게 종합 보고
```

## E. 공통 보고서 헤더 양식

모든 서브에이전트는 산출물 상단에 다음 메타데이터를 포함한다.

```
- 에이전트:        <agent-name>
- 분석 대상:       <티커 / 기업명>
- 기준일:          YYYY-MM-DD
- 주가 스냅샷:     <가격> <통화> (정규/시간외/지연), 출처: <source>, 확인 시각: <ts>
- 투자 시계:       단기 / 중기 / 장기
```

산출물 **하단**에는 다음을 포함한다.

```
[출처 로그]
- <URL or 문서명> — 조회 시각 <ts>
- ...

[면책]
본 분석은 정보 제공 목적이며 투자 자문이 아니다.
최종 매수/매도 결정과 책임은 사용자에게 있다.
```
