# /analyze — 종합 매수/매도 분석

당신(메인 세션)은 **오케스트레이터**다. 아래 절차를 그대로 수행한다. 각 단계는
`.claude/CLAUDE.md` 의 전역 규칙을 반드시 준수한다.

## 인자 파싱

- 사용자 입력: `$ARGUMENTS`
- 입력에서 다음을 추출한다.
  - **종목**: 티커(예: `AAPL`, `005930.KS`) 또는 기업명(예: `삼성전자`)
  - **재무제표 포함 여부**: 입력에 `재무제표`, `financials`, `with financials`
    등의 명시적 키워드가 있을 때만 `포함`
- 인자가 비어 있거나 종목을 식별할 수 없다면 사용자에게 다음을 먼저 묻는다.
  1. 분석 대상 종목 (티커 또는 기업명)
  2. 분석 범위 — 재무제표 분석 포함 여부 (기본: 미포함)
  3. 투자 시계 — 단기 / 중기 / 장기 (기본: 중기)

## 0. 기준일·주가 스냅샷 고정 (규칙 A-1, A-2)

1. **오늘 날짜를 먼저 확인**한다(`WebSearch` 또는 시스템 시간). `as-of date` 로 고정.
2. 대상 종목의 **가장 최신 주가**를 신뢰 가능한 출처에서 가져온다.
   다음을 함께 기록한다: 가격 · 통화 · 정규/시간외/지연 · 출처 · 확인 시각.
3. 위 정보를 `[Run Context]` 블록으로 저장하여 모든 서브에이전트 위임 시 함께 전달한다.

```
[Run Context]
- 대상: <티커 / 기업명>
- 기준일(as-of): YYYY-MM-DD
- 주가 스냅샷: <price> <ccy> (정규/시간외/지연), 출처: <src>, 확인 시각: <ts>
- 투자 시계: 단기 / 중기 / 장기
- 재무제표 분석: 포함 / 미포함
```

## 1. 중립 데이터 수집 — 병렬 위임

다음 에이전트를 **단일 메시지에 병렬 호출**한다. 위임 프롬프트마다
`[Run Context]` 와 분석 요구사항을 명시한다.

- `macro-analyst` — 글로벌 거시 환경이 대상 종목/섹터에 미치는 영향
- `micro-analyst` — 산업 구조·경쟁·시장 점유율·수급
- `technical-analyst` — 가격·밸류에이션 멀티플·과거 밴드·동종 비교
- `sentiment-analyst` — 최신 뉴스·컨센서스·목표주가·심리
- **`financial-analyst`** — 사용자가 **재무제표 분석을 명시적으로 요청한
  경우에만** 호출. 그렇지 않으면 절대 호출하지 않는다.

## 2. 가치 평가

- `value-investor` 에 1단계 산출물을 모두 전달하고, 버핏/멍거식 원칙으로
  내재가치 범위(보수/기본/낙관) 와 안전마진을 산출하게 한다.

## 3. 토론 — 진짜 블루팀 vs 레드팀 양면 대결 (2-Phase)

동일한 데이터(1·2 단계 결과)를 양 팀에 전달한다.

- 🟢 **블루팀(BUY 측)**: `bull-researcher`
- 🔴 **레드팀(SELL 측)**: `bear-researcher` + `risk-manager`

### Phase A — 개회 진술 (병렬)
- 블루팀과 레드팀을 **동시에 launch**.
- 각 팀에게 `[PHASE: A]`를 명시하고, 상대 팀 산출물은 *제공하지 않는다*.
- 사전 반박·가정 반박 금지. 자기 입장만 명확히.

### Phase B — 교차 반박 (병렬, Phase A 완료 후)
- 블루팀에 `[PHASE: B]` + `[RED OPENING]` 블록(레드팀 Phase A 전문) 전달.
- 레드팀에 `[PHASE: B]` + `[BLUE OPENING]` 블록(블루팀 Phase A 전문) 전달.
- 각 팀은 상대 팀의 *실제 텍스트*에서 인용한 후 반박. 오케스트레이터가
  묘사한 가상 논거 반박 금지(strawman 방지).

### Phase C (선택) — 최종 진술
- Phase B의 반박을 받은 후, 각 팀이 마지막 정리 진술. 1라운드로 충분하면 생략.

## 4. 검증

- `fact-checker` 를 호출해 1~3단계의 모든 산출물의 사실·수치·날짜·출처·논리를
  독립 재검증.
- 판정이 **"반려"** 면 지목된 단계를 재실행한다(최대 2회까지). 통과 시 5단계로.

## 5. 최종 평가

- `evaluator` 에게 사자/팔자/검증 결과를 전달.
- 출력 형식은 evaluator 정의를 따른다 (BUY/HOLD/SELL · 확신도 · 결정적 근거
  3가지 · 반대 측 최강 논거 · 무효화 조건 · 데이터 기준일 · 출처 · 면책).

## 6. 사용자 보고

오케스트레이터는 evaluator 결과를 사용자에게 다음 구조로 정리해 보고한다.

1. **한 줄 요약** — BUY / HOLD / SELL + 확신도
2. **핵심 근거** — 결정적 근거 3가지
3. **반대 의견** — 반대 측 가장 강한 논거와 채택하지 않은 이유
4. **무효화 조건** — 이 판단을 뒤집을 트리거
5. **부록** — 기준일, 주가 스냅샷, 핵심 출처, 면책 문구

사용자가 더 깊은 분석을 원하면, 어떤 에이전트의 어떤 부분을 더 깊게 볼지를 물어보고 재위임한다.
